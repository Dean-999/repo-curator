# Use tiered canonical-result governance

Canonical-result governance uses four scoped states: `CANDIDATE`, `PROVISIONALLY_CANONICAL`, `USER_CONFIRMED`, and `UNRESOLVED`. The Skill may provisionally identify a result when independent evidence classes strongly agree and no material counter-evidence exists; minor non-safety gaps may be presented for batch acceptance; only material conflicts trigger one evidence-specific user question. If the user cannot decide, the result stays unresolved and all related bundles remain protected. User confirmation records project intent but does not erase counter-evidence, assert scientific validity, or authorize filesystem mutation. This avoids both unsafe automatic winners and a per-result approval burden that would make the Skill little more than a questionnaire.
